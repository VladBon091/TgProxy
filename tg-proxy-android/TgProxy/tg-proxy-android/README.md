# TG Proxy (Android)

Локальный MTProto-прокси для Telegram. Приложение поднимает на телефоне сервер `127.0.0.1:1443`;
Telegram подключается к нему как к обычному MTProto-прокси, а приложение пересылает трафик в датацентры
Telegram по нескольким маршрутам и само выбирает рабочий:

1. **Прямой WebSocket** `wss://kwsN.web.telegram.org/apiws` (для DC2/DC4 — через IP `149.154.167.220`);
2. **Cloudflare Worker** (ваш бесплатный воркер, код в приложении);
3. **Свой домен на Cloudflare** (`kwsN.<домен>`);
4. **Прямой TCP** (резерв).

Если маршрут не отвечает за 8 секунд, запрос Telegram автоматически повторяется на следующем маршруте,
а удачный маршрут запоминается.

## Сборка APK без Android Studio
Загрузите папку в свой репозиторий GitHub → вкладка **Actions** → **Build APK** → Run workflow →
скачайте артефакт `TgProxy-debug-apk`. Локально: Android Studio (File → Open) или `gradle assembleDebug` (Gradle 8.9+, JDK 17, Android SDK).

## Использование
1. Запустить → «Применить в Telegram» (или скопировать ссылку `tg://proxy?...`).
2. Нажмите «Диагностика сети»: она отправляет настоящий запрос к датацентру по каждому маршруту и показывает,
   что работает у вашего оператора прямо сейчас.
3. Если прямые маршруты не работают — разверните Cloudflare Worker: Cloudflare → Workers → Create →
   вставьте код (кнопка «Скопировать код Cloudflare Worker») → Deploy → впишите `имя.аккаунт.workers.dev` в настройки.
4. Отключите оптимизацию батареи для приложения, иначе Android может усыпить сервис.

## Самопроверка ядра
`tools/selftest/` — стенд на Python + Kotlin (фейковый «датацентр» и «клиент Telegram»):
`CERT=... KEY=... python3 -I tools/selftest/selftest.py` после `tools/selftest/kc.sh`.
Он проверяет протокол и переключение маршрутов, но не доступность Telegram из вашей сети.

Идея и протокол — по мотивам проекта Flowseal/tg-ws-proxy.
